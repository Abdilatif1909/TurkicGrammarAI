# 3. Turkic Lexical Resources

## 3.1 Language Coverage

The lexical resources used in this study cover eight Turkic language varieties: Uzbek, Turkish, Azerbaijani, Kazakh, Kyrgyz, Turkmen, Uyghur, and Old Turkic. This selection was designed to represent both contemporary Turkic languages and a historically important earlier variety. The modern languages differ in geography, script traditions, standardization history, and available digital resources, while Old Turkic provides a diachronic reference point for historical comparison. The resulting collection is therefore not a uniform corpus in the sense of identical language coverage or identical resource maturity. Instead, it is a multilingual research resource intended to support comparative analysis across related languages.

The language set includes both Oghuz languages, such as Turkish, Azerbaijani, and Turkmen, and non-Oghuz languages, such as Uzbek, Uyghur, Kazakh, and Kyrgyz. These languages share inherited Turkic structures, including productive suffixing morphology and many cross-language lexical relationships, but they also differ in phonology, orthography, contact influence, and modern vocabulary. Kazakh and Kyrgyz include Cyrillic-script data in the repository resources, while Turkish, Azerbaijani, Turkmen, Uzbek, and Old Turkic resources include Latin-script or transliterated forms. Uyghur is represented in the raw word data and embedding resource statistics, but repository audits note that normalized Uyghur clean data is not yet present in the same form as the other normalized language files. This mixed status is important for interpreting both coverage and evaluation.

Table 1 summarizes the language distribution used for the manuscript resource package. It reports 18,314 Uzbek records, 15,798 Turkish records, 10,372 Azerbaijani records, 10,582 Kazakh records, 10,499 Kyrgyz records, 10,102 Turkmen records, 13,916 Uyghur records, and 10,417 Old Turkic records. The same table reports lemma and root counts for each language, with Uzbek having 5,465 lemmas and 5,466 roots, Turkish having 4,366 lemmas and roots, Uyghur having 4,324 lemmas and roots, and the remaining modern and historical varieties having approximately 2,534 to 2,824 lemmas and roots. These figures indicate broad multilingual coverage, but they should be interpreted as repository resource statistics rather than as a complete description of the lexicons of the languages.

## 3.2 Lexical Resource Construction

The repository organizes lexical resources through several related data layers. The word datasets are stored by language under the backend data directory and provide the core surface-form inventory. These files contain language-specific word records with fields such as word form, lemma, root, meaning, language identifier, and source metadata. The embedding dataset then combines lexical records with additional linguistic information used for representation learning, including morphology-related fields, cognate group metadata, and historical lineage information where available.

Lemma and root inventories provide another layer of structure. In the manuscript table package, lemmas and roots are counted as lexical abstraction units used to group related surface forms. In the broader repository, morphology files include language-specific lemma resources and rule files. The dataset manifest records morphology resources for Azerbaijani, Kazakh, Kyrgyz, Old Turkic, Turkish, Turkmen, Uyghur, and Uzbek, together with rule inventories and universal feature metadata. These files support analysis of roots, lemmas, suffix behavior, and derivational patterns. However, the audit reports caution that morphology lemma files can be small in top-level structure relative to rule files, and that coverage should not be treated as expert-certified completeness.

Root inventories and root distribution statistics are also available as repository artifacts. They support the analysis of lexical bases and provide a bridge between word-level data and morphology-aware representation. In the present paper, root information is used as structured linguistic evidence rather than as an independently validated etymological database. This distinction is necessary because repository audits identify provenance and review status as continuing limitations. The metadata fields are therefore useful for reproducible computational experiments, but they do not by themselves certify linguistic correctness.

## 3.3 Dataset Statistics

The manuscript resource statistics are summarized in Table 1 and Table 2. Table 1 reports the language-level distribution described above, including record, lemma, and root counts for each of the eight represented language varieties. Table 2 summarizes the embedding-oriented lexical resource. It reports 100,000 embedding dataset records across eight languages, 88,712 unique surface forms, 26,797 unique lemmas, and 26,798 unique roots. It also reports 75,429 records with morphology features, 23,018 records with a cognate group, 2,000 unique cognate groups, 25,018 records with historical lineage, and 215,162 historical lineage entries.

The dataset manifest provides a complementary view of the raw word files. Excluding the language manifest file, the canonical word files contain 100,030 word records: 14,902 Uzbek records, 14,905 Turkish records, 11,903 Azerbaijani records, 11,904 Kazakh records, 11,905 Kyrgyz records, 11,904 Turkmen records, 11,679 Uyghur records, and 10,928 Old Turkic records. These raw counts differ from the manuscript table counts because the tables summarize the embedding-oriented package rather than only the original word JSON files. This distinction is important: raw word files, normalized files, morphology resources, and embedding records are related but not identical resource views.

The normalized word data contains clean files for Azerbaijani, Kazakh, Kyrgyz, Old Turkic, Turkish, Turkmen, and Uzbek. The dataset manifest reports 7,594 normalized Azerbaijani records, 7,997 Kazakh records, 8,000 Kyrgyz records, 7,835 Old Turkic records, 9,486 Turkish records, 7,579 Turkmen records, and 10,000 Uzbek records. The same manifest explicitly notes that no normalized Uyghur clean file is present. This gap affects how normalized-resource statistics should be interpreted and is one reason the present study distinguishes between available raw data and fully normalized data.

The lexical diversity report further indicates that the dataset is broad in surface forms but narrow in lemma and root seed inventory. It reports a high type-token ratio for the inspected dataset and notes that the design is useful for morphology coverage, but limited for dictionary, search, and scientific evaluation use cases. This observation is relevant to the present embedding study because a morphology-oriented resource can support generation and coverage experiments while still requiring stronger lemma validation for publication-level lexical claims.

## 3.4 Cognate and Historical Resources

The cognate layer represents cross-language lexical relationships through cognate sets and alignment-oriented metadata. The dataset manifest lists `backend/data/cognates/cognates.json` with 1,000 Turkic cognate sets and `backend/data/cognates/cross_language_cognates.json` with 2,000 cross-language sets. It also lists cognate alignment rules and sample seed material. In the embedding-oriented resource summarized in Table 2, 23,018 records are linked to a cognate group, and the package contains 2,000 unique cognate groups. These resources are central to the paper because they provide explicit cross-language anchors for cognate-aware representation learning.

The historical layer includes historical forms and lineage metadata. The dataset manifest lists `backend/data/historical/historical_forms.json` with 2,000 records covering Azerbaijani, Kazakh, Kyrgyz, Old Turkic, Turkmen, Turkish, and Uzbek. Table 2 reports 25,018 records with historical lineage and 215,162 historical lineage entries in the embedding-oriented resource. Repository audit notes also identify proto-style identifiers in generated semantic-index material, including forms such as Proto-Turkic-like IDs. These links are treated as metadata for historical lineage and representation experiments, not as independently certified reconstructions.

Old Turkic has a specific role in this resource design. It is represented as a language variety in the word files, manuscript tables, morphology resources, benchmarks, and historical resources. In this study, Old Turkic provides an anchor for diachronic comparison and for testing whether historically related forms can support multilingual lexical organization. However, the existence of Old Turkic records does not imply complete historical coverage. The resource should be understood as a computationally structured historical layer that requires careful provenance and expert review before strong historical-linguistic claims are made.

## 3.5 Dataset Quality and Limitations

The repository audits identify several quality considerations that affect interpretation of the lexical resources. First, some root-level statistics are stale relative to the canonical backend data. For example, an older words dataset audit reported 60,000 records and missing Uyghur data, while the later dataset manifest and language balance report show that Uyghur data is present and that raw word files total approximately 100,030 records. For this reason, the present section uses the manuscript tables, dataset manifest, and language balance report rather than older stale statistics.

Second, language identifiers are not fully normalized across all records. Audits report that some files contain both full language names and canonical codes, such as `azerbaijani` and `az`, or `old` and `otk`. Such inconsistencies can affect filtering, grouping, and statistics if not handled carefully. The normalized data partially addresses this issue, but the absence of a normalized Uyghur clean file means that normalization is not yet uniform across all eight language varieties.

Third, duplicate and overlap behavior must be interpreted carefully. The duplicate analysis reports no identical lexical-entry duplicates, but it identifies 2,655 cross-language homographs and a global duplicate word percentage of 4.3574. Such overlap is not necessarily an error in a related-language dataset, because shared forms can reflect cognacy, borrowing, or common technical vocabulary. At the same time, it complicates automatic evaluation because identical strings across languages may not always correspond to identical meanings or historical relationships.

Fourth, several audit reports identify synthetic, generated, or projection-based resource limitations. Some Uyghur resources are reported as projected from an existing Turkic lexical inventory, and cognate or historical fields may include generated metadata. Gold datasets are also described as candidate resources requiring expert review rather than completed expert-certified gold standards. Consequently, the lexical resources are suitable for reproducible computational experiments and manuscript preparation, but not for unsupported claims of complete linguistic validity.

Finally, provenance remains a central limitation. The dataset audit recommends more detailed source identifiers, citations, licenses, curation status, generation metadata, reviewer information, and review status. These limitations do not prevent the use of the resource for studying cognate-aware multilingual embeddings, but they determine the strength of the claims that can be made. In this paper, the resources are therefore treated as a transparent research dataset with documented limitations, and Tables 1 and 2 are used to describe the available computational evidence rather than to assert exhaustive coverage of Turkic lexical knowledge.
